# ✦ Farstar — ربات فروش VPN برای پنل ثنایی

ربات تلگرام فارسی با منوی شیشه‌ای (Inline)، مدیریت داخل ربات، مینی‌اپ جداگانه مدیر و مشتری، داشبورد راست‌چین، اتصال چندسرور به 3x-ui، خرید و تحویل اشتراک، تمدید، پرداخت و پشتیبانی. پروژه مستقل از دیتابیس پنل کار می‌کند.

**نسخه 1.2.0 · هدف سازگاری: 3x-ui v3.11.0**، آخرین انتشار رسمی بررسی‌شده در ۲۶ اکتبر ۲۰۲۶. مسیرهای API و تبدیل ساختار کاربر از کد و OpenAPI همین نسخه بررسی شده‌اند. تست‌های خودکار با سرویس‌های شبیه‌سازی‌شده اجرا می‌شوند؛ نصب واقعی نیز اتصال خواندنی پنل و تلگرام را بررسی می‌کند.

## پرداخت مستقیم کارت‌به‌کارت

کاربر پلن را انتخاب می‌کند، مبلغ دقیق همان فاکتور را به کارت فروشگاه می‌ریزد و عکس فیش را برای همان سفارش می‌فرستد. **عکس فیش از ابتدا با دکمه‌های «تأیید و تحویل اشتراک» و «رد رسید» برای مدیر ارسال می‌شود.** تأیید مدیر، سفارش را مستقیم وارد صف ساخت می‌کند؛ موجودی کیف پول افزایش نمی‌یابد و مشتری پرداخت دیگری انجام نمی‌دهد. سفارش دارای فیش تا زمان بررسی منقضی یا قابل پرداخت مجدد نیست؛ با رد رسید، همان سفارش برای ارسال فیش جدید باز می‌شود.

تحویل در تلگرام یک تصویر QR اختصاصی با برند Farstar، نام حساب، حجم و تاریخ اعتبار است و لینک اشتراک در زیر همان تصویر قرار دارد. برند و نوشته‌ها بیرون ناحیه امن QR قرار دارند. همان کارت از دکمه QR در ربات و مینی‌اپ نیز قابل دریافت است. تأیید هم‌زمان یا تکراری، اشتراک یا موجودی تکراری ایجاد نمی‌کند. موجودی قبلی، هدیه‌ها و پاداش دعوت همچنان قابل استفاده‌اند؛ شارژ دستی کیف پول با فیش حذف شده است. اگر خرید کارت‌به‌کارت ناموفق نیاز به بازپرداخت داشته باشد، بازپرداخت بانکی دستی برای مدیر ثبت می‌شود و اعتبار کیف پول خودکار ایجاد نمی‌شود.

## چند اینباند و شماره‌گذاری

در ویرایش سرور، «همه اینباندهای فعال و سازگار» را فعال کنید تا یک هویت و لینک اشتراک، حجم و اعتبار مشترک روی تمام اینباندهای فعال پنل داشته باشد. ساخت با یک درخواست چنداینباندی انجام می‌شود؛ بازیابی عملیات ناقص فقط اتصال‌های باقی‌مانده را اضافه می‌کند. افزودن اینباند جدید به پنل، در همگام‌سازی دوره‌ای اشتراک‌های فعال صادرشده توسط ربات شناسایی می‌شود. سرویس‌های دستی قبلی پنل تغییر نمی‌کنند. حالت تکی هم در دسترس است. پروتکل‌های سازگار: VLESS، VMess، Trojan، Shadowsocks، Hysteria و TUIC.

نام حساب هنگام ساخت سفارش پرداخت‌شده رزرو می‌شود. پیش‌فرض `CLIENT_NAME_PREFIX=FARSTAR_` و `CLIENT_NUMBER_START=405` است. ربات بزرگ‌ترین شماره موجود در پنل و رزروهای محلی را بررسی می‌کند؛ مثلاً اگر `FARSTAR_405` موجود باشد، ساخت بعدی `FARSTAR_406` خواهد بود. شمارنده بعد از ری‌استارت باقی می‌ماند، تمدید نام قبلی را حفظ می‌کند و تلاش مجدد شماره تازه‌ای مصرف نمی‌کند. نام سرویس‌های قبلی بازنویسی نمی‌شود. APIهای ساخت چنداینباندی و attach مطابق [مستندات رسمی 3x-ui 3.11](https://github.com/MHSanaei/3x-ui/blob/v3.11.0/docs/content/docs/en/reference/api/clients.mdx) استفاده شده‌اند.

## ربات و مینی‌اپ‌ها

`/start` منوی Inline و `/admin` مدیریت بومی ربات را باز می‌کند. مدیر از داخل تلگرام پلن، موجودی، رسید، تیکت، تنظیمات کارت، تست، دعوت، وضعیت فروش سرور، کدها، پیام همگانی و بکاپ را مدیریت می‌کند. تغییر وضعیت یک سرویس نیاز به تأیید صریح همان اقدام در رابط دارد.

مینی‌اپ مشتری در `/app` و مدیر در `/admin-app` قرار دارند. ورود واقعی فقط با `initData` امضاشده تلگرام انجام می‌شود؛ نقش مدیر با شناسه‌های `ADMIN_IDS` در سرور کنترل می‌شود. در محیط واقعی هیچ ورود نمایشی وجود ندارد. تنظیم HTTPS و اجرای جداگانه در [راهنمای مینی‌اپ](docs/MINIAPPS.md) توضیح داده شده است.

آموزش فقط برای Happ است: اندروید، آیفون/آیپد، ویندوز، مک، لینوکس، Android TV و Apple TV. انتخاب دستگاه در ربات یک GIF و مراحل فارسی ارسال می‌کند. GIFها **راهنمای شماتیک ساخته‌شده برای پروژه** هستند؛ ضبط صفحه برنامه نیستند. لینک‌های نصب از [صفحه رسمی Happ](https://www.happ.su/main) و مخازن رسمی آن گرفته شده‌اند.

## تماشای نسخه نمایشی

در همین پروژه، محیط مجازی و وابستگی‌ها نصب شده‌اند:

```powershell
.\.venv\Scripts\python.exe -m farstar demo
```

داشبورد: [http://localhost:8081](http://localhost:8081). ورود محیط نمایشی: `admin` / `farstar-demo-2026`.

دیتابیس نمایشی `data/demo.db` است. داده‌های نمایشگر نمونه‌اند و در حالت demo هیچ پیام تلگرامی، پرداخت یا درخواست به پنل فرستاده نمی‌شود. این حالت فقط روی loopback اجرا می‌شود. برای کار واقعی از `run` و دیتابیس اصلی استفاده کنید؛ داده‌های نمونه منتقل نمی‌شوند.

## نصب تازه

Python 3.11 یا جدیدتر لازم است. برای محیط قابل تکرار از نسخه‌های قفل‌شده استفاده کنید.

### Windows

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m farstar setup
```

یا `scripts/start.ps1` را برای نصب اولیه و اجرا، و `scripts/start.ps1 -Demo` را برای نمایش اجرا کنید.

### Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m farstar setup
```

اجرای کمکی: `sh scripts/start.sh` یا `sh scripts/start.sh demo`.

دستور setup فایل `.env` را با رمز مدیریت و کلید تصادفی می‌سازد؛ فایل قبلی را بازنویسی نمی‌کند. **رمز محیط واقعی در ADMIN_PASSWORD فایل .env است و با رمز demo تفاوت دارد.**

## راه‌اندازی ربات واقعی

۱. از BotFather یک ربات بسازید و توکن را در `.env` قرار دهید. شناسه عددی تلگرام مدیران را به صورت آرایه JSON وارد کنید:

```dotenv
BOT_TOKEN=123456:YOUR_BOT_TOKEN
ADMIN_IDS=[111111111,222222222]
APP_NAME=Farstar
CURRENCY=XTR
```

۲. ربات را اجرا کنید:

```powershell
.\.venv\Scripts\python.exe -m farstar run
```

داشبورد واقعی به طور پیش‌فرض [http://localhost:8080](http://localhost:8080) است. با ADMIN_USERNAME و ADMIN_PASSWORD فایل `.env` وارد شوید.

۳. در «سرورها» اطلاعات پنل را ثبت کنید:

| فیلد | نمونه / توضیح |
|---|---|
| آدرس پنل | `https://panel.example.com:2053/your-web-base-path`؛ شامل مسیر اختصاصی، بدون `/panel/api` |
| توکن API | توکن معتبر با scope `admin` از پنل؛ توکن `monitor` برای ساخت سرویس کافی نیست |
| ورود جایگزین | نام کاربری و رمز پنل، در صورت نداشتن توکن؛ برای پنل دارای 2FA از API token استفاده کنید |
| اینباند | شناسه عددی یک اینباند فعال موجود در پنل |
| آدرس پایه اشتراک | مثلاً `https://sub.example.com:2096/sub`؛ مطابق Subscription پنل، بدون شناسه کاربر |
| ظرفیت | تعداد سرویس‌های دارای اعتبار به‌علاوه سفارش‌های رزروشده برای این سرور |

«بررسی اتصال» را بزنید و بعد در «پلن‌های فروش» اولین پلن را بسازید. استفاده از اشتراک خود پنل باعث می‌شود جزئیات TLS، REALITY، XHTTP، هاست‌ها و ترنسپورت توسط همان پنل تولید شوند. تنظیمات Xray و اینباند موجود را ربات ایجاد یا بازنویسی نمی‌کند.

۴. در تلگرام `/start` را بزنید، قوانین را بپذیرید و یک تست بگیرید. سپس یک خرید با محیط آزمایشی Telegram Stars انجام دهید و تحویل/QR/تمدید را با زیرساخت خودتان بررسی کنید. قیمت پلن‌ها در حالت XTR عدد صحیح استار است.

ربات با long polling کار می‌کند. فقط **یک نمونه** از برنامه و یک polling مصرف‌کننده برای هر توکن اجرا کنید. وبهوک موجود به صورت خودکار حذف نمی‌شود؛ اگر قبلاً ربات دیگری وبهوک ثبت کرده، ابتدا آگاهانه از تنظیمات همان سرویس آن را حذف کنید. وضعیت تعارض در داشبورد دیده می‌شود.

## تنظیمات مهم

| متغیر | کاربرد |
|---|---|
| `SECRET_KEY` | کلید رمزنگاری اطلاعات پنل؛ تغییر آن دسترسی به اطلاعات ذخیره‌شده قبلی را از بین می‌برد |
| `CURRENCY` | `XTR` برای استار، `IRT` برای تومان؛ پیش از اولین تراکنش انتخاب کنید |
| `PUBLIC_URL` | آدرس نهایی داشبورد، مثلاً `https://shop.example.com` |
| `COOKIE_SECURE` | در محیط HTTPS روی `true` قرار بگیرد |
| `REQUIRED_CHANNEL` | نام کاربری `@channel` یا شناسه کانال؛ ربات باید امکان بررسی عضویت داشته باشد |
| `CHANNEL_URL` | لینک عضویت کانال، اگر عضویت اجباری است |
| `REFERRAL_PERCENT` | درصد پاداش اولین خرید موفق دعوت‌شده، پیش‌فرض ۱۰ |
| `TRIAL_ENABLED` | فعال بودن تست؛ حجم `TRIAL_GB` و مدت `TRIAL_HOURS` |
| `TERMS_TEXT` | متن اختیاری قوانین فروشگاه؛ در صورت خالی بودن، متن عمومی پروژه نمایش داده می‌شود |
| `BACKUP_HOURS` | فاصله بکاپ خودکار، پیش‌فرض ۲۴ ساعت؛ ۱۴ نسخه آخر باقی می‌ماند |

در حالت پرداخت دستی، شماره کارت و نام صاحب حساب را می‌توانید از بخش «تنظیمات و راه‌اندازی ← پرداخت کارت‌به‌کارت» ثبت کنید. این اطلاعات در دیتابیس ربات ذخیره می‌شود و برای تغییر آن نیازی به ری‌استارت پنل یا ربات نیست.

برای فروش خدمات دیجیتال درون تلگرام، پرداخت پیش‌فرض با Stars پیاده‌سازی شده است؛ این همان روش مقرر در [مستندات رسمی تلگرام](https://core.telegram.org/bots/payments-stars) است. مسیر رسید دستی به صورت پیش‌فرض خاموش است. اگر برای عملیات دستی خارج از جریان پرداخت تلگرام به آن نیاز دارید، واحد پول را از ابتدا IRT و `MANUAL_PAYMENTS=true`، `CARD_NUMBER` و `CARD_HOLDER` را تنظیم کنید. این مسیر درگاه بانکی خودکار یا تأیید واقعی تراکنش بانکی ندارد؛ مدیر باید هر رسید را با گردش حساب تطبیق بدهد.

کاربر مسدودشده یا کاربری که هنوز عضو کانال نیست همچنان می‌تواند پشتیبانی پرداخت دریافت کند. دریافت successful_payment نیز به دلیل مسدود شدن کاربر نادیده گرفته نمی‌شود.

## نصب با Docker

ابتدا `.env` را با setup بسازید و تنظیم کنید، سپس:

```sh
docker compose up -d --build
docker compose logs -f --tail=100
```

دیتابیس در volume پایدار `farstar-data` نگهداری می‌شود. سرویس با کاربر غیر root و فایل‌سیستم عمدتاً فقط‌خواندنی اجرا می‌شود. پورت داشبورد روی loopback میزبان منتشر می‌شود. روی سرور برای دسترسی شخصی می‌توانید از تونل SSH استفاده کنید:

```sh
ssh -L 8080:127.0.0.1:8080 user@your-server
```

برای انتشار روی دامنه، یک reverse proxy با HTTPS نصب کنید؛ نمونه پیکربندی در `docs/Caddyfile.example` قرار دارد. PUBLIC_URL را روی دامنه و COOKIE_SECURE را true بگذارید و سرویس را دوباره ایجاد کنید. Docker Compose یک worker داخلی دارد؛ تعداد replica یا uvicorn workers را افزایش ندهید.

برای نصب بدون Docker، نمونه unit در `docs/farstar.service` موجود است. مسیر `/opt/farstar`، کاربر `farstar` و دسترسی نوشتن پوشه data را مطابق سرور خود آماده کنید. اجرای unit هم‌زمان با Docker یا اجرای دستی برای همان دیتابیس/توکن توصیه نمی‌شود.

برای نصب کنار پنل دارای مشتری، [راهنمای نصب مستقل](docs/SAFE_DEPLOYMENT.md) و unit با محدودیت منابع در `docs/farstar-robot.service` آماده است؛ این روش از پورت آزاد loopback و دیتابیس کاملاً جدا استفاده می‌کند.

## مدیریت روزمره

- `/admin` در تلگرام: خلاصه فروش و صف بررسی مدیران تعریف‌شده.
- `/reply 12 متن پاسخ`: پاسخ مدیر به تیکت ۱۲.
- `/receipt شناسه`: نمایش تصویر و تأیید/رد رسید.
- داشبورد «سفارش‌ها»: تلاش مجدد سفارش ناموفق و بازپرداخت خرید ناموفق.
- بازپرداخت خرید ناموفق، ابتدا کاربر احتمالی در پنل را غیرفعال و بررسی می‌کند؛ بدون دسترسی به پنل بازپرداخت خودکار انجام نمی‌شود. مبلغ کیف پول به کیف پول و مبلغ استار با refundStarPayment بازمی‌گردد. بازپرداخت تمدید یا سرویس تحویل‌شده نیاز به بررسی دستی دارد.
- محدودیت IP توسط خود پنل و زیرساخت آن اعمال می‌شود؛ رفتار آن با محدودیت دستگاه متفاوت است.
- هشدارها از آخرین داده همگام‌شده ساخته می‌شوند. هر چرخه مانیتورینگ حداکثر ۳۰ سرویس را به ترتیب قدیمی‌ترین snapshot بررسی می‌کند؛ در نصب‌های بزرگ فاصله به‌روزرسانی بیشتر می‌شود.

```sh
python -m farstar backup
python -m farstar doctor
```

خروجی CSV و دانلود بکاپ در «گزارش‌ها» نیز وجود دارد. بکاپ با SQLite backup API ساخته می‌شود تا WAL در آن لحاظ شود. `.env` و SECRET_KEY را جدا از دیتابیس پشتیبان بگیرید. بکاپ دیتابیس حاوی لینک اشتراک و اطلاعات مالی است.

برای بازیابی: برنامه/polling را متوقف کنید، از دیتابیس فعلی نسخه پشتیبان نگه دارید، فایل بکاپ سالم را جایگزین DATABASE_PATH کنید و فایل‌های WAL/SHM مربوط به دیتابیس قبلی را کنار بگذارید. این کار را فقط وقتی هیچ فرآیندی دیتابیس را باز نگه نداشته انجام دهید. SECRET_KEY اصلی را حفظ کنید، سپس برنامه را اجرا و `doctor` را بررسی کنید. برای volume داکر، سرویس را متوقف و فایل بکاپ را با یک ابزار مدیریت volume به مسیر `/app/data/farstar.db` برگردانید؛ volume را حذف نکنید.

## اعتبارسنجی توسعه

```sh
python -m pip install -e ".[dev]"
python -m pytest -q
ruff check farstar tests
node --check farstar/static/app.js
```

تست‌ها مالی اتمیک، مالکیت، انقضا، تخفیف و هدیه، پرداخت استار و تکرار، ساخت با پاسخ نامطمئن، تمدید تکرارشده، تبدیل ClientRecord جدید، پاداش دعوت، بازپرداخت، CSRF، ورود، بکاپ و پردازش واقعی updateهای ربات را پوشش می‌دهند. شرح دقیق قرارداد در `docs/ARCHITECTURE.md` است.

## محدوده نسخه

این نسخه فروش مستقیم با چند سرور را پیاده‌سازی می‌کند. نمایندگی با سهمیه مستقل، انتخاب مسیر خودکار بین پنل‌ها، درگاه بانکی زنده و تغییر سرور اشتراک موجود پیاده‌سازی نشده‌اند. هدف اتصال، API جدید نسخه 3.11 است؛ API قدیمی addClient/updateClient و نسخه‌های قدیمی پنل مسیر جداگانه ندارند. قابلیت‌های اینباند پیشرفته از اشتراک رسمی پنل عبور می‌کنند، اما کیفیت اتصال نهایی و دسترسی سرور باید روی زیرساخت واقعی آزمایش شود.
